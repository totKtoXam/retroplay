# CLAUDE.md

Jinaly · Retro 3D — совместные ретроспективы + 3D-шутер в браузере. React 19, TypeScript, Three.js, Vinext, Cloudflare Workers + D1. Подробности — `README.md`, анализ проекта — `docs/analys/`.

## Команды

В PowerShell используйте `npm.cmd`.

- `npm.cmd run typecheck` — проверка типов (обязательна после правок).
- `npm.cmd test` — юнит-тесты (обязательны после правок).
- `npm.cmd run lint` — oxlint; на момент 2026-09-11 уже падает на старых ошибках, новые не добавлять.
- `npm.cmd run test:integration` — только при запущенном `localhost:3000`.

Основная ветка — `main`. Перед мержем своей ветки подтягивать изменения из `main`.

## Модели субагентов

- **По умолчанию** субагенты Claude работают на **Sonnet 5 с effort `xhigh`** («Sonnet Extra»). Настроено в `.claude/settings.json`: `env.CLAUDE_CODE_SUBAGENT_MODEL = claude-sonnet-5` и `modelSettings.claude-sonnet-5.effortLevel = xhigh`.
- **Повышение до Opus** — через параметр `model: "opus"` при запуске агента, только когда это оправдано: архитектурные решения, сетевой код и конкурентность, безопасность и права доступа, сложные баги через несколько файлов, или Sonnet уже не справился с задачей. Причину повышения указывать в сообщении пользователю.
- **В названии каждой задачи указывать модель** префиксом: `[sonnet] Аудит 3D-клиента`, `[opus] Перевод сети на Durable Objects`. Для Antigravity — `[agy gemini-3.8-flash-high] …`. Так пользователь видит, какая модель выполняет задачу.

## Делегирование Antigravity (`agy` CLI)

**По умолчанию задачи делает Claude.** Antigravity (`agy`) подключается только тогда, когда это реально даёт лучший результат, чем сделать самому: быстрее по времени или заметно экономнее по лимитам Claude — при сопоставимом качестве. Antigravity слабее Claude; если есть сомнение, что он справится, или Claude сделает быстрее и лучше — делать самому (или своими агентами).

Подходит для Antigravity:
- объёмные механические правки по чёткой спецификации (массовые переименования, чистка неиспользуемых импортов/CSS, удаление мёртвых файлов по готовому списку);
- шаблонный код или тесты по точному описанию, в изолированных файлах;
- работа, которую можно запустить параллельно с задачами Claude в других файлах.

Не подходит (делать самому):
- мелкие правки — написать для Antigravity задание дольше, чем сделать правку;
- баги, требующие рассуждений через несколько файлов, сетевой код, конкурентность, безопасность, права доступа, миграции БД;
- всё, где ошибку трудно заметить при ревью.

Как запускать:
- Модель: `gemini-3.8-flash-high` (Gemini 3.8 Flash, High).
- Задание — отдельным файлом в scratchpad: точный список файлов, которые можно менять, запрет на git и shell-команды, конкретные строки и ожидаемый результат.
- **Перед запуском показать пользователю полный текст промпта** и дождаться его подтверждения. Без подтверждения `agy` не запускать.
- Запуск — фоновой задачей, чтобы пользователь видел весь вывод Antigravity: `agy -p <задание> --model gemini-3.8-flash-high --output-format stream-json --mode accept-edits --print-timeout 30m`, вывод дублировать в лог через `Tee-Object`.
- Файлы Antigravity не должны пересекаться с файлами, которые в это же время правит Claude.
- После завершения Claude обязательно проверяет результат: diff, `typecheck`, `test`.
- Запуск `agy` может блокироваться режимом разрешений Claude Code — тогда не обходить, а спросить пользователя.
- В headless-режиме `agy` без правила `read_file(...)` в `permissions.allow` файла `~/.gemini/antigravity-cli/settings.json` не может читать даже свой workspace: всё недостающее отклоняется молча. Правило ставит пользователь (Claude Code не даёт Claude менять разрешения другого агента). Без правила `agy` не запускать.
- В задании давать абсолютные пути к файлам worktree: на слова «текущая папка» `agy` идёт в основной checkout.
- Отклонённые разрешения (`denied_actions` в результате) показывать пользователю в чате. Если он согласен, он добавляет узкое правило, после чего разговор продолжается через `--conversation <id>`.

## Метрики Antigravity

После **каждого** запуска Antigravity добавлять строку в `docs/antigravity-metrics.md` (формат и поля описаны там). Когда накопится 10 засчитанных запусков, подвести итог и вместе с пользователем решить, нужен ли Antigravity вообще. Ориентир: если меньше 60 % работ принято без доработок или доработка Claude сопоставима по времени с самостоятельным выполнением — отказаться от Antigravity.
