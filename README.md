# Jinaly · Retro 3D

Совместные ретроспективы в браузере: игровой мир от третьего лица и обычная доска работают с одним состоянием комнаты. React, TypeScript, Three.js, Vinext, Cloudflare D1.

## Запуск

Нужны Node.js 22.13+ и npm. В PowerShell используйте `npm.cmd`.

```sh
npm ci
npm run db:local
npm run dev -- --host 0.0.0.0
```

Откройте http://localhost:3000. Создайте комнату, введите имя и передайте ссылку участникам. Вход через Google и письма подключаются отдельно ([docs/auth-setup.md](docs/auth-setup.md)); без них работают гостевой вход и регистрация по почте. Для подключения с другого компьютера нужен доступный ему адрес сервера: `localhost` обозначает компьютер самого участника. Веб-публикация Sites по умолчанию доступна только владельцу; для команды необходимо отдельно настроить аудиторию сайта.

Комнаты и карточки сохраняются в D1. Локальная база находится в `.wrangler` и не попадает в Git или веб-публикацию. Локальное и опубликованное приложения имеют разные базы. Не удаляйте `.wrangler`, если нужны локальные комнаты.

## Управление

| Действие                    | Ввод                                                          |
| --------------------------- | ------------------------------------------------------------- |
| Начать / продолжить игру    | Клик по миру или «Играть»                                     |
| Камера                      | Движение мыши без удержания кнопок                            |
| Курсор для меню             | Esc                                                           |
| Движение                    | WASD                                                          |
| Прыжок                      | Пробел                                                        |
| Сесть / встать              | C                                                             |
| Лечь                        | Двойное C                                                     |
| Присесть / медленный шаг    | Удерживать Ctrl / Shift                                       |
| Первое / третье лицо        | V или кнопки FPP / TPP                                        |
| Прицеливание / перезарядка  | Удерживать ПКМ / R                                            |
| Планшет / стикер            | Колесо выбирает good / bad / stop / start, E открывает стикер |
| Вернуть камеру за персонажа | F                                                             |
| Приближение / отдаление     | Alt + колесо, кнопки камеры                                   |
| Быстрые предметы            | 1–4: краскомёт, конфетти, планшет, гранаты                    |
| Снаряжение                  | Q / I; клик подтверждает выбор, Esc отменяет                  |
| Краска / конфетти           | 1 / 2, затем ЛКМ                                              |
| Участники, задержка, FPS    | Удерживать Tab или кнопка участников                          |

Переключение V сохраняет направление прицеливания; первое лицо показывает руки с оружием, третье лицо защищено от столкновений камеры со стенами. Выбор обзора сохраняется на устройстве. ПКМ приближает прицел, R перезаряжает: краска — 24 заряда, конфетти — 6, запас бесконечный. Смена инструмента отменяет незавершённую перезарядку. Анимации приседания, прицеливания и перезарядки передаются другим участникам.

Первый клик активирует обзор и не стреляет. При разрешённом Pointer Lock курсор захватывается и камера вращается неограниченно. При запрете захвата во встроенном браузере обзор работает внутри окна; у его краёв продолжается горизонтальный поворот. Esc возвращает курсор. Панели приостанавливают игровой ввод. Персонаж плавно следует за направлением камеры; A/D — движение боком, S — назад. Чувствительность и инверсия камеры настраиваются локально.

Для Ctrl+W и других сочетаний, зарезервированных браузером, включите полный экран кнопкой в шапке. При поддержке браузером запрашивается Keyboard Lock. Встроенное окно может не поддерживать системный захват; разрешения браузера приложение не обходит.

Время суток, сезон и погоду (ясно, пасмурно, туман, дождь, буря, снегопад, метель или «авто» — смена по сезону) меняет ведущий кнопкой над миром; сезоны работают и на боевых картах. Ветер зависит от погоды, всё время меняет силу и направление, сносит игроков и снаряды; индикатор под прицелом показывает, куда сносит. Ведущий может выключить влияние ветра там же. Оформление и интерьер находятся в настройках мира. Настройки встречи в шапке содержат приватность и анонимность; название редактируется нажатием на него. Блок FPS и пинга открывает локальные настройки графики и лимит 20 / 30 / 60 / 120 FPS. Есть темы Наурыза, Дня единства, Дня Республики, Дня независимости, Нового года и горного лагеря. Краска постепенно исчезает; игровые эффекты не меняют карточки.

## Оформление, инструменты и музыка

Два визуальных стиля: Tactical — контрастное окружение с каменными и металлическими павильонами, корпусами кампуса, цветными порталами, дальними горами и отражениями неба; Аниме — контурные персонажи, парящие острова и лепестки. Авторская модель AERO имеет отдельные поверхности лица, одежды, перчаток и обуви; её суставы сохраняют общие анимации движения. Tactical использует собственные модели и материалы с ориентиром на читаемость тактических шутеров. Графика работает на Three.js / WebGL. Экономичный режим использует статические тени, высокий — динамические мягкие тени и деликатный bloom. Время суток, сезоны и интерьер работают в обоих стилях.

В 3D доступны четыре быстрых слота. Вращение или нажатие колеса открывает круг вариантов текущего предмета. Колесо и стрелки меняют подсветку, клик / Enter подтверждают выбор, Esc отменяет. Q открывает снаряжение. Планшет хранит выбранный раздел; E открывает цветной стикер с одним текстовым полем. Сохранение — галочка или Ctrl+Enter. Инструменты рисования доступны в обычной доске.

Краскомёт имеет восемь цветов. Конфетти: классика, звёзды, снежки, сердца, цифры, лепестки, кометы и шаңырақ. Гранаты: пиньята, взрыв красок, снежный шар, валентинка, пиксельная и метеор. Бросок ЛКМ, задержка взрыва 1,1 секунды, радиус 4 м. Урон: краска 20 HP, конфетти 5 HP, гранаты 45 HP; самоповреждения нет. HP рассчитывается сервером. Возрождение по умолчанию через 5 секунд, ведущий задаёт 1–30 секунд в настройках мира. Старые пакеты позиции после возрождения игнорируются.

Анонимные участники носят бумажные пакеты со смайликом; сервер не передаёт их имена. Приватный стикер виден другим участникам как цветная карточка с каракулями. Текст и остальные приватные поля удаляются из ответа сервера; автор видит и раскрывает свою запись.

Jinaly Radio запускается по нажатию Play: четыре оригинальные синтезированные аранжировки, выбор трека, пауза и громкость. Музыку слышит только текущий пользователь; автоматического запуска нет. Аудиофайлы не загружаются: музыка создаётся Web Audio API на устройстве. Звуки событий включаются отдельно.

## Вход и аккаунты

Аккаунт не обязателен: комнату можно создать и пройти ретро гостем, по ссылке-приглашению, как и раньше. Вход нужен, чтобы вернуться к своим комнатам с другого устройства или после очистки cookie.

Личные настройки запоминаются на устройстве и у гостя. У вошедшего они ещё и переезжают вместе с аккаунтом: тема, управление и прицеливание, вид от первого или третьего лица, облик персонажа, музыка, звуки встречи, цвет краски и стили предметов. Изменения уходят в аккаунт в фоне, а с других устройств подтягиваются при открытии страницы, возврате на вкладку и входе; если одно и то же поменяли на двух устройствах сразу, каждая настройка берётся оттуда, где её меняли. Графика, качество, лимит FPS и визуальный пакет остаются на устройстве: они зависят от железа.

Способы входа — почта с паролем и Google. Кнопка входа в шапке лобби открывает диалог: вход, регистрация, восстановление пароля и профиль (имя в комнатах, пароль, выход). Регистрация сразу входит в аккаунт и забирает себе текущую гостевую личность, если она свободна, — созданные до регистрации комнаты и карточки остаются у человека.

Письмо с подтверждением уходит при регистрации; до подтверждения нельзя восстановить пароль. Ссылка сброса действует час и срабатывает один раз, после смены пароля остальные устройства разлогиниваются. Десять неверных паролей подряд замораживают аккаунт на 15 минут.

Вход через Google и отправка писем включаются переменными окружения (`.dev.vars` локально, секреты wrangler на сервере) — [docs/auth-setup.md](docs/auth-setup.md). Без них кнопка Google скрыта, а ссылки подтверждения пишутся в консоль воркера и на `localhost` показываются прямо в диалоге.

Пароли хранятся как PBKDF2-HMAC-SHA256 из WebCrypto (bcrypt и argon2 в Workers недоступны); число итераций записано в самой строке хеша, поэтому его можно поднять — пароль пересчитается при следующем входе. В базе лежат только хеши cookie-токенов сессий и ссылок из писем.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
# При работающем localhost:3000:
npm run test:integration
npm run build
```

`lint` проверяет код приложения, API и тесты; в `components/ui` оставлены только используемые shadcn-компоненты. Весь TypeScript входит в typecheck. CI (`.github/workflows/ci.yml`) запускает typecheck, тесты и lint на push в `main` и в pull request.

Модель проверяется на права ведущего, приватность, анонимность, голосование, архив и импорт. HTTP-проверка создаёт отдельные тестовые сессии и комнаты, проверяет конкурентные записи, лимит голосов, историю, отмену, изоляцию комнат и передачу краски; отдельная проверка проверяет HP, задержку гранат, дедупликацию урона, возрождение, старые пакеты позиции и анонимность. Затем тестовые комнаты архивируются.

## Архитектура и ограничения

- Сервер выдаёт HttpOnly cookie; публичный ID участника — SHA-256 от сессионного секрета, а не сам секрет. У вошедшего в аккаунт публичный ID берётся из его записи (`users.public_id`), поэтому остальной код о способе входа не знает.
- Содержимое чужих приватных карточек и чужие активные голоса исключаются из ответа сервера. Проверка прав выполняется в API.
- Изменения комнат проходят через контроль версии и атомарный пакет D1; история хранит последние 40 операций.
- Карты живут в `lib/maps`. Хаб оставлен как есть: своя сцена (`components/world-scene.ts`) и свои столкновения. Боевые карты («Особняк», «Базар», «Горный лагерь», «Ледниковая долина» — самая большая, 120 × 112 м, впятеро больше горного лагеря) описаны данными — блоки, пандусы, цилиндры, вода, точки спавна, — и из одного описания строятся и сцена (`components/world-arena-scene.ts`), и столкновения, поэтому картинка и физика не расходятся. Границы карты — её же ограничитель: и клиент, и сервер зажимают позу ровно в `bounds`, так что большая карта не требует правок в движке. Карту выбирает ведущий в настройках мира; при смене все получают новую жизнь и переносятся на точки спавна новой карты. Столкновения учитывают стойку (стоя 1,8 м, присев 1,2 м, лёжа 0,6 м): в низкий лаз можно пройти только пригнувшись, а встать под низким потолком нельзя.
- В правом нижнем углу — миникарта: план сверху из тех же данных, что и сцена, своя стрелка и союзники. По M план разворачивается на весь экран. Враг попадает на план, только если кто-то из своих держит его в узком секторе вокруг прицела и видит не через стену (`lib/spotting.ts`); отметка живёт пару секунд и показывает последнее известное место. Так план не показывает того, чего игрок не видит глазами. Проверка идёт на клиенте — это правило игры, а не защита от читов: позиции всех игроков клиенту по-прежнему приходят.
- На боевых картах идёт командный бой, на хабе — каждый сам за себя. Новый игрок попадает в меньшую команду, ведущий может перекинуть любого. Ведущий настраивает огонь по своим (включение и долю урона), формат матча (бой с возрождением или раунды без возрождения), лимит убийств, время и число побед в раундах. Убийство своего не даёт ни фрага, ни очка. Счёт, номер раунда и итог матча ведёт объект комнаты, они видны в HUD.
- Карточки доски хранятся отдельными строками таблицы `notes`, а `rooms.state` — остальная комната без них (`lib/room-store.ts`): правка карточки пишет одну строку, а не всю комнату. История хранит не копию комнаты, а прежние значения изменённого; отмена возвращает их. Комнаты, сохранённые до этого формата, держат карточки внутри `rooms.state` и переносятся в таблицу при первой записи.
- Каждая комната — Durable Object (`worker/room-hub.ts`), в памяти которого живут позиции, HP, выстрелы и расчёт боя (`lib/room-hub-core.ts`). Клиент подключается к нему по WebSocket (`/api/rooms/:id/socket`): шлёт позу до 20 раз в секунду и получает состояние игроков 10 раз в секунду. Доска, настройки и история остаются в D1; об их изменении объект рассылает `refresh`, и клиент перечитывает комнату по HTTP. Горячие поля раз в 2 секунды копируются в D1. Если сокет недоступен, клиент сам переходит на прежний HTTP-опрос, который обслуживает тот же объект.
- Попадания считает сервер с компенсацией задержки: выстрел несёт `seenAt` — серверное время мира, который видел стрелок, — и жертвы проверяются в позах из истории на этот момент (не дальше 250 мс назад; гранаты — по позам в момент взрыва). Позы от клиента проверяются: быстрее бега, внутрь стены и сквозь стену нельзя — такая позиция не принимается, а после 1,5 с отказов клиент синхронизируется с сервером. Высоту (прыжки, падения с крыш) сервер не проверяет.
- Серверные боты живут в объекте комнаты (`lib/bot-brain.ts`) и играют по тем же правилам, что люди: шаг проходит проверку `applyPresence`, выстрел — `fireEffect`. Знают они только то, что видят (сектор обзора, дальность, чистая линия огня) и слышат (чужие выстрелы рядом). Ходят по сетке проходимости карты, которая строится один раз на карту. Список ботов — в `rooms.state` (`bots`), строк в `members` у них нет. Каждый бот занимает место игрока. Без людей в сети боты спят. Играют только в командном бою.
- Режим «Предатель» (в духе Among Us, карта «Корабль») ведёт тот же объект комнаты (`lib/impostor.ts`). Партию начинает ведущий, нужно от 4 до 15 человек в сети. Сервер раздаёт роли и задания и проверяет всё, что можно проверить: убийство — только предатель, вблизи, без стены и после перезарядки; репорт — рядом с телом; кнопка — у стола; задание — у пульта и не быстрее мини-игры. Тайна ролей держится на сервере: в этом режиме каждый сокет получает свой снимок (`impostorView`), где есть только своя роль, союзники-предатели (для предателя), свои задания и общий прогресс. Живые не получают поз призраков и не узнают о смерти до собрания; голоса видны после голосования, роли — в конце партии. Оружия в режиме нет. Кто слышит голос (во время игры живые молчат, призраки говорят только между собой), сервер решает для отметки «говорит», а сам звук идёт напрямую между браузерами, поэтому его глушит клиент. Выбывает тот, кто 45 секунд не шлёт присутствие и не держит сокет.
- Геометрия объединяется по материалам, конфетти используют instancing, 3D загружается отдельным модулем. Качество и ограничитель кадров независимы: 20 / 30 / 60 / 120 FPS (120 снимает ограничение — кадры выдаёт сам браузер). Проверено 30 FPS в текущем встроенном браузере; производительность на конкретном слабом ноутбуке требует проверки на устройстве.
- Гость после очистки cookie теряет свои комнаты: восстановление возможно только с аккаунтом. Комнаты, созданные до входа в уже существующий аккаунт, остаются у гостевой личности — переносится только регистрация. Регистрация не ограничена по адресу источника — при публичном размещении нужен внешний лимит (правило Cloudflare). Управления ролями и исключения участников пока нет. Не использовать непредсказуемую ссылку комнаты как полноценную корпоративную модель доступа.
- Spreo использован как функциональный ориентир. По обновлённому запросу Jinaly развивается как самостоятельная игра и инструмент ретроспектив; точная копия интерфейса и полный паритет интеграций не являются целью. [Исходный аудит](docs/spreo-audit.md).

## Боты

Ведущий добавляет ботов в настройках комнаты («Комната → Боты»): уровень, сторону («в меньшую команду», красные или синие) и количество — до 16 за раз и до 32 в комнате, в пределах «Максимума участников». Уровень можно поменять уже играющему боту.

| Уровень | Реакция, мс | Разброс | Обзор, м | В голову |
|---|---|---|---|---|
| Слабый | 560–820 | ×3,2 | 18 | — |
| Средний | 340–500 | ×1,9 | 24 | 5 % |
| Сильный | 220–310 | ×1 | 30 | 15 % |
| Эксперт | 150–200 | ×0,6 | 36 | 35 % |

Слабый к тому же не уходит в укрытие и медленнее бегает. Уровень не даёт ни урона, ни знания сквозь стены: меняются только человеческие качества. В матчах 5 на 5 по три минуты на каждой боевой карте (обе стороны) каждый уровень обыгрывает соседний снизу: эксперт слабого — 300 : 56, эксперта сильный — 143 : 218, сильный среднего — 184 : 102, средний слабого — 193 : 74. Зеркальные матчи равных ботов сходятся вничью. Такт 31 бота на «Ледниковой долине» — около 1,5 мс (95-й процентиль — 6 мс).

### API ботов

Тех же ботов можно добавлять без браузера — от имени ведущего, по ключу `BOTS_API_TOKEN` из `.dev.vars` (без ключа API выключен):

```sh
curl -k -H "Authorization: Bearer $BOTS_API_TOKEN" https://192.168.56.70:3001/api/rooms/<id>/bots
curl -k -H "Authorization: Bearer $BOTS_API_TOKEN" -H "Content-Type: application/json"   -d '{"action":"add","level":"expert","team":"red","count":5}' https://192.168.56.70:3001/api/rooms/<id>/bots
```

Действия: `add` (`level`: `weak` / `medium` / `strong` / `expert`, `team`: `red` / `blue` / `auto`, `count`), `level` (`id`, `level`), `remove` (`id`), `clear`. Ответ — список ботов комнаты с их командой и счётом. `scripts/bots.mjs` остаётся внешним нагрузочным ботом: он играет через HTTP и пишет журнал ошибок сервера.

## Продакшен-сборка и LAN-сервер

```sh
npm run build
npm start -- --ip 0.0.0.0 --port 3001
```

`npm start` запускает собранный Worker из `dist/` через wrangler с той же локальной базой `.wrangler/state`, что и `npm run dev`. Без `--persist-to .wrangler/state` wrangler создал бы пустую базу рядом с `dist/server/wrangler.json`.

LAN-сервер работает в продакшен-режиме: `retro3d.service` запускает `start-lan.sh` (порт 3001). `scripts/deploy.ps1` (или `scripts/deploy.sh`) проверяет код локально, отправляет `main` и по SSH запускает на сервере `scripts/server-deploy.sh`: `npm ci` при изменении `package-lock.json`, миграции D1, тесты, `npm run build`, перезапуск сервиса и проверку HTTP. Во время сборки (около минуты) старый сервер может отдавать ошибки для статических файлов.

Миграции D1 применяются до перезапуска сервиса, а базу в это время держит ещё работающий сервер. На нагруженной комнате шаг падает с `SQLITE_BUSY: database is locked` — тогда деплой стоит делать, когда в комнате никого нет.

### HTTPS на LAN-сервере

Адрес сервера — `https://192.168.56.70:3001`. HTTPS здесь нужен не ради шифрования в локальной сети: браузер считает `http://<ip>` незащищённым источником и не отдаёт такой странице микрофон, поэтому по http голосовой чат (T и Y) не работает ни у кого.

`start-lan.sh` при первом запуске делает самоподписанный сертификат в `.wrangler/lan-cert` (адреса в SAN, срок два года) и передаёт его wrangler. Сертификат лежит на диске, а не создаётся заново при каждом запуске, — иначе после каждой перезагрузки сервера все игроки снова видели бы предупреждение браузера.

Что об этом нужно знать:

- Каждый игрок один раз пройдёт «Подробнее → Перейти на сайт»: сертификат никем не заверен. Чтобы предупреждения не было совсем, сертификат нужно добавить в доверенные на каждой машине.
- Старые ссылки вида `http://192.168.56.70:3001` перестают открываться — порт слушает только HTTPS.
- Вход через Google: адрес возврата собирается из адреса запроса, поэтому в консоли Google к разрешённым redirect URI нужно добавить `https://192.168.56.70:3001/api/auth/google/callback` (или задать `GOOGLE_REDIRECT_URI` в `.dev.vars`).

## Публикация

Проект зарегистрирован в Sites через `.openai/hosting.json`. Публикуйте собранный Worker вместе с миграциями из `drizzle`; не переносите локальную базу или сессионные cookie в исходный код. Сначала проверка и сборка, затем сохранение версии и публикация для выбранной аудитории.

- [vinhhien112/img2obj](https://github.com/vinhhien112/img2obj) (MIT) — скил `object-to-threejs-procedural`: по картинке строит процедурную Three.js-модель кодом. Нужен Python 3.10+.
