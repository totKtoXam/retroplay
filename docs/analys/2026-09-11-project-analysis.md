## Вердикт

Игровая часть сделана добротно: своя коллизия, общие для клиента и сервера хитбоксы, эффекты, камера FPP/TPP, 41 юнит-тест. Слабые места — сетевая архитектура, ряд реальных багов и два огромных файла (`components/world.tsx` ~3800 строк, `components/room-app.tsx` ~3400 строк).

Состояние проверок на момент анализа: `typecheck` — проходит, `npm test` — 41/41, `lint` — 27 ошибок, CI в репозитории нет.

### Переводить ли БД на NoSQL, а бэкенд на Rust?

Нет. Узкое место не в SQL и не в TypeScript, а в модели обмена данными:

- В 3D-режиме клиент опрашивает сервер каждые **120 мс** (`room-app.tsx:568`), ~8 запросов/с на игрока. Каждый запрос пишет в D1 и заново разбирает всё состояние комнаты.
- Состояние комнаты уже хранится как NoSQL-документ (один JSON в колонке `rooms.state`). Любая правка карточки перезаписывает весь блоб, история хранит 40 полных копий. Переезд на Mongo/Dynamo закрепит именно эту проблему. Остальные данные (комнаты, участники, заявки, счёт) реляционные.
- Серверная нагрузка — пересечение луча с капсулой для 8–50 игроков, это микросекунды. Хитбоксы и урон в `lib/game-items.ts` общие для клиента и сервера; Rust потребовал бы дублировать их вручную.

**Рекомендация:** Cloudflare Durable Objects + WebSocket (один объект на комнату). Горячие данные (позиции, HP, выстрелы) — в памяти объекта, тик 20–30 Гц, авторитарный расчёт попаданий с лаг-компенсацией. Холодные данные (карточки, голоса, история) — в SQLite объекта или D1, карточки отдельными строками, история патчами. Язык остаётся TypeScript.

Rust имеет смысл только для отдельного игрового сервера с физикой 60 Гц на 100+ игроков; даже тогда — как WASM-модуль, а не переписывание бэкенда.

## 2. Сервер и сеть

- `ensureJoinRequestsTable()` выполняет 3 DDL-запроса на каждый запрос API; `ensureCombatColumns` делает `ALTER TABLE` при старте изолята. Схему нужно вести миграциями: `0004` отсутствует в `drizzle/meta/_journal.json`, в `db/schema.ts` нет `join_requests`, колонок `kills/deaths/assists/recent_damage/immune_until` нет ни в одной миграции. При переносе в миграции учесть, что на существующих базах эти колонки уже созданы рантаймом.
- Строковые литералы в двойных кавычках в SQL (`status="pending"`, `recent_damage="{}"`) работают только из совместимости SQLite. Нужны одинарные кавычки.
- Сервер доверяет клиенту позицию и точку попадания: возможны телепорт и стрельба сквозь стены, лаг-компенсации нет.
- Состояние комнаты — JSON-блоб без ограничения размера; может упереться в лимит строки D1 (~2 МБ), после чего все записи в комнату падают.
- Список публичных комнат разбирает JSON последних 100 комнат ради фильтра; видимость и тип доступа стоит вынести в колонки.
- Нет оптимистичных обновлений и ключа идемпотентности: при таймауте 6 с запись может пройти, а повтор создаст дубль.
- `publicState` генерирует новый invite-токен при каждом вызове, если у старой комнаты нет `access`.
- История анонимизируется по *текущей* настройке комнаты: выключение анонимности раскрывает авторов старых записей.

## 3. Геймплей шутера

- **Командных боёв в коде нет** — только «каждый сам за себя». Для командного режима нужны: поле `team` у участника, точки возрождения команд, проверка своих в `resolveCombat`, счёт по командам.
- Одна точка возрождения `(0, 0, 4)` на всех — провоцирует кемперство.
- Удалённые игроки на возвышениях всегда в позе прыжка (`world.tsx:2315`: `p.y > 0.01`), предсказание движения идёт сквозь стены (`world.tsx:2271`).
- Лимит FPS по умолчанию 30; `powerPreference: 'low-power'` включает встроенную видеокарту на ноутбуках с двумя GPU.
- Мышь обрезается до ±120 за событие (`world.tsx:1619`), быстрые флики теряются.

## 4. Производительность 3D

- Каждый выстрел обходит всю сцену с рекурсивным `getObjectById` (`world.tsx:1180`), при прицеливании гранатой — каждый кадр. Список целей нужно кэшировать.
- Каждый кадр: обходы дерева аватаров, `localStorage.getItem`, новые `Vector3`/`Raycaster`, перерисовка теней статичного мира.
- `setShots` на каждый выстрел перерисовывает весь компонент; `RoomApp` перерисовывает `World` ~8 раз в секунду.
- Потеря WebGL-контекста не восстанавливается — канвас остаётся чёрным.

## 5. Код и чистка

- Разбить `world.tsx`: один `useEffect` ~2000 строк. Модули движка: renderer, input, player-controller, camera-rig, weapons, projectiles/vfx, remote-players, loop; HUD через `useSyncExternalStore`.
- Разбить `room-app.tsx`: хуки `useRoomSync`, `useLocalPrefs`, `useRoomEvents`; экраны и панели — отдельные компоненты; экспорт/импорт — в `lib/export.ts`.
- Из 60 файлов `components/ui` используются 7. Неиспользуемые зависимости: `date-fns`, `recharts`, `embla-carousel-react`, `react-day-picker`, `cmdk`, `input-otp`, `react-resizable-panels`, `@shadcn/react`. `shadcn` — CLI, место в devDependencies.
- В `app/globals.css` 166 блоков селекторов объявлены повторно, ~40 классов нигде не используются.
- Нет i18n: русские строки в клиенте и сервере; сервер лучше перевести на коды ошибок.
- Добавить CI (GitHub Actions): typecheck + lint + test. Починить 27 ошибок lint, включая ошибки React Compiler про refs в `world.tsx`.
- CSV-экспорт не экранирует формулы (`=`, `+`, `-`, `@`).
